# 🏛️️ الهيكلية التقنية لمنصة موجة البيان

تعتمد منصة **موجة البيان** على هيكلية ميكرو-سيرفس مبسطة تعمل كنقطة نهاية (API) واحدة، ومبنية على نمط **RAG** (Retrieval-Augmented Generation) لتحسين جودة ردود الذكاء الاصطناعي.

## المكونات الأساسية (Core Components)

1. **الواجهة الأمامية / واجهة برمجة التطبيقات (FastAPI Backend):**
   * تعمل كبوابة لاستقبال الطلبات ومعالجتها.
   * مسؤولة عن تقديم واجهة الدخول (`/login`) باستخدام `Jinja2 Templates`.
   * مسؤولة عن تقديم واجهة تفاعلية لاختبار النظام (`/docs` - Swagger UI).

2. **محرك التضمين (Embedding Engine):**
   * يستخدم **Gemini Embedding** (من Google) لتحويل النصوص والوثائق والاستفسارات إلى متجهات رقمية (Vectors).
   * حجم المتجه (Vector Size) يعتمد على النموذج المستخدم (عادةً 768).

3. **قاعدة البيانات المتجهية (Vector Database):**
   * تستخدم **Qdrant** لتخزين المتجهات.
   * تقوم بالبحث الدلالي (Semantic Search) للعثور على الوثائق الأكثر صلة بسؤال المستخدم عبر حساب مسافة جيب التمام (Cosine Distance).

4. **نموذج التوليد (LLM Generator):**
   * يستخدم **Gemini Flash (1.5 أو 2.5)** لصياغة الإجابة النهائية.
   * يستقبل سياق الوثائق المسترجعة من Qdrant بالإضافة إلى سؤال المستخدم الأصلي لضمان دقة الإجابة وعدم خروجها عن السياق (Hallucination Prevention).

## تدفق البيانات (Data Flow)
1. يرسل المستخدم سؤالاً عبر المسار `/ask`.
2. يتم تحويل السؤال إلى متجه رقمي باستخدام `Gemini Embedding`.
3. يتم البحث عن أقرب 3 متجهات في `Qdrant` مطابقة لسؤال المستخدم.
4. تُجمع النصوص المرتبطة بهذه المتجهات وتُرسل كـ "سياق" إلى نموذج `Gemini Flash`.
5. يقوم النموذج بصياغة الرد ويعيده للمستخدم مع ذكر "المصادر".
